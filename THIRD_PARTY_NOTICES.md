La licence MIT de ce dépôt concerne nos fichiers originaux ; chaque dépendance conserve sa propre licence. Nous ne recopions pas ici le code ou les binaires de ces projets.

## Briques système et dépendances indirectes

La VM utilise Debian, Linux, systemd, OpenSSH, Git, Python, curl, jq et ripgrep. Ces composants proviennent des dépôts système, avec leurs notices de copyright sous `/usr/share/doc/<paquet>/copyright`. Le bootstrap relève les versions installées dans le manifeste système. Il ne redistribue pas ces composants sous la licence du projet. [ripgrep](https://github.com/BurntSushi/ripgrep) accélère la recherche de fichiers et de contenu pour les outils Hermes, avec un binaire système lancé à la demande.

Sources : [Debian](https://www.debian.org/), [Linux](https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/), [systemd](https://github.com/systemd/systemd), [OpenSSH portable](https://github.com/openssh/openssh-portable), [Git](https://github.com/git/git), [CPython](https://github.com/python/cpython), [SQLite](https://sqlite.org/src/doc/trunk/README.md), [curl](https://github.com/curl/curl), [jq](https://github.com/jqlang/jq). Le binaire Python dédié conserve notamment la notice CPython et les licences de ses bibliothèques embarquées ; la licence MPL-2.0 de son système de construction ne remplace pas ces notices.

Les paquets Python indirects restent décrits dans le `uv.lock` d'Hermes au commit verrouillé. Le manifeste de runtime conserve pour chaque paquet sa version, ses déclarations de licence et ses liens de projet lorsque ses métadonnées les fournissent. Une déclaration absente ou ambiguë reste visible comme telle ; elle n'est pas inventée. L'ajout d'une redistribution de code ou de binaires nécessitera de conserver les notices exigées par leurs licences.

[setuptools](https://github.com/pypa/setuptools) et [wheel](https://github.com/pypa/wheel) construisent le paquet local Hermes. Leurs versions et empreintes sont dans `deploy/runtime/build-requirements.lock` ; cette étape séparée évite de télécharger implicitement une version différente de l'outil de construction à chaque installation.

## Comment cet inventaire évolue

Tout composant ajouté doit avoir une origine, une version identifiable, une explication de sa fonction et une raison du choix. Son état passe à « installé » ou « validé » seulement après vérification réelle. Les outils simplement envisagés restent dans l'[étude de l'écosystème](docs/ecosysteme.md), avec leurs sources et les critères à vérifier avant adoption.
